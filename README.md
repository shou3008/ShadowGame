# 影リフティング — 重力加速度の官能評価実験装置

Web カメラに映った人のシルエット（影）を当たり判定にし、落ちてくるボールを影で弾き続ける
一人用のリフティング。**ボールの重力加速度を独立変数**とし、水準ごとの主観評価（官能評価）を
取るための実験装置です。

- 人物抽出: [BodyPix](https://github.com/tensorflow/tfjs-models/tree/master/body-pix)（TensorFlow.js）
- 影の描画: WebGL2 によるグリッドモザイク
- 当たり判定: 占有率フィールド（影をボール半径ぶん膨張させた連続場）

---

## 必要環境

- WebGL2 と Web カメラに対応したモダンブラウザ（Chrome / Edge 推奨）
- カメラ利用のため **`https://` か `localhost`** で配信する必要があります（`file://` 直開きは不可）

ライブラリは CDN から読み込むため `npm install` は不要です。VS Code の **Live Server** で
`index.html` を開くだけで動きます。

---

## 実験の設計

| 項目 | 内容 |
| --- | --- |
| **独立変数** | ボールの重力加速度。5 水準（700 / 1200 / 2100 / 3600 / 6000 px/s²） |
| **課題** | リフティング。落ちてくるボールを影（体）で弾き続ける |
| **操作** | プレイヤーが制御するのは**影の法線の向きだけ**。体をどの角度で差し出すかでボールの行き先が決まる |
| **提示** | 試行ごとにランダム順。**被験者に重力値は見せない（盲検）** |
| **試行** | 固定 60 秒。落としても自動で復活し、時間まで続く |
| **主要従属変数** | **最長連続ラリー**（一度も落とさずに続いた最大ヒット数） |
| **主観評価** | アプリでは取らない。紙 / Google Form で別途 |

### 反発係数が 1.0（完全弾性）である理由

これは好みではなく物理的な要請です。影を静止した壁として扱うと、ボールにエネルギーを与える
経路がありません。影の高さを `y_w`、跳ね返り後の最高到達点を `h` とすると

```
h_{n+1} = e²·h_n + y_w·(1 − e²)     →  h → y_w に収束
```

`e < 1` だとボールは弾まなくなり**体の上で止まります**（e=0.9 でも 10〜15 回で死ぬ）。
これは技量では止められない、物理で決まった寿命であり、従属変数が技量ではなく
物理定数で決まってしまいます。`e = 1.0` ならエネルギーが保存し、ミスは
「取り逃がして床に落とす」ときだけ起きます。

**`PHYSICS.restitution` を 1.0 から下げてはいけません。**

## 使い方（実験者向け）

1. Live Server で `index.html` を開く
2. コンソールに `TF backend: webgl` と出ることを確認する
   （`cpu` ならステータス欄が赤くなる。推論が遅すぎて実験に使えないので、先に直すこと）
3. 参加者IDを入力（例 `P01`）して **開始**
4. **練習**（45 秒・基準重力）→ 本試行 5 回（各 60 秒）
5. 各試行の後にツールバーが戻るので、その間に被験者へ評価用紙を記入してもらう
6. 全試行が終わったら **CSV(試行)** と **CSV(イベント)** を書き出す

提示順は参加者IDのハッシュから決まるので、**同じIDなら同じ順序が再現します**。

### 盲検について

重力値は画面に一切表示されません。値は `Session` の内部と CSV の中だけに存在します。
試行が始まるとツールバーも自動的に隠れます。

### 環境の固定（重要）

カメラと被験者の立ち位置は**セッション中ずっと動かさないでください**（床にテープを貼る）。
被験者がカメラに近づくとシルエットが大きくなり、課題が易しくなります。
CSV の `mean_body_coverage` が試行間で 20% 以上ドリフトしていたら、そのセッションは疑ってください。

## 検証

### `?selftest=1` — 物理の自動検査

`http://localhost:5500/index.html?selftest=1` で開くとコンソールに結果が出ます。
**すべて PASS でなければ実験を回してはいけません。** 各テストは「重力以外の要因が
結果に混入していないこと」を直接検査しています。

| # | 検査内容 |
| --- | --- |
| 1 | 自由落下が `½gt²` に一致（積分器の健全性） |
| 2 | 減衰がフレーム長に依存しない（旧実装にあった「高重力ほど空気抵抗が強い」交絡の不在） |
| 3 | 全 5 水準で速度クランプが発火しない（高重力条件だけ物理が切られていないこと） |
| 4/5 | 完全弾性のエネルギーが全 5 水準で保存する |
| 6 | 跳ね返り後の最高到達点が重力に依存しない |
| 7 | 傾き θ の面に垂直落下 → 反射角が `2θ`（「体の角度で跳ね返る向きが決まる」） |
| 8 | 影を上向きに掃引してもエネルギーが発散しない |

### `?debug=1` — 当たり判定の可視化

占有率フィールドと法線を重ねて表示します。確認すること:

- 赤枠の等値線が影の輪郭をボール半径ぶん外側でなぞっているか
- 手を振ったとき等値線が**滑らかに**動くか（100ms 刻みでカクつくなら時間外挿が効いていない）
- `mask age` が何 ms か（これが当たり判定の遅れ）

## 調整ポイント

すべて `src/settings.js` に集約しています。**重力水準以外の値は全条件で共通です。
「手触りを良くするために重力ごとに変える値」を足してはいけません。独立変数が汚れます。**

- **重力水準**: `GRAVITY_LEVELS`
- **試行時間・練習・繰り返し**: `EXPERIMENT`
- **当たり判定の閾値**: `PHYSICS.shadowThresh`
  占有率 O は「ボールの円板が影に埋まっている割合」なので、
  上げるほどボールは深くめり込んでから跳ねる（沈み込み = `2R·θ`）。
  下げるほど細い部位まで当たる（最小反応幅 = `2R(1 − √(1−θ))`）。
  現在 0.25（沈み込み 30px / 最小幅 16px ≒ 3.4cm。指は拾わない）
- **影の追従性**: ツールバーの「品質」。ステータス欄の `推論 N` が影の更新回数

### 影が体に追いつかないとき

シルエットは**推論が終わったときにしか更新されません**。描画は常に 60fps ですが、
推論が 10fps なら影も 10fps でしか動きません。ステータス欄の `60 fps / 推論 25` の
**右側**が追従性を決める値です。

当たり判定は `∂O/∂t` による**時間外挿**で 60fps 相当に滑らかにしていますが、
推論が遅いほど外挿の誤差が増えます。打撃ごとの `infer_age_ms` を CSV に記録しているので、
**高重力条件だけ `infer_age_ms` が大きくないか**を必ず事後確認してください。
差があれば、遅延が独立変数と交絡しています。

## CSV

### `trials.csv`（1 試行 1 行）
`rally_max` が主要従属変数。`gravity_px_s2` / `gravity_log2_ratio` が独立変数。

物理定数を全行に重複させています。パイロットで定数を調整するため、
**CSV が自己記述的でないと「どの設定で取ったデータか」を後から復元できなくなる**ためです。

異常検知用の列:
- `clamp_hits` — 非ゼロならその試行は疑う（速度クランプが物理を切った）
- `max_ball_energy` — 試行間で増え続けるならエネルギーが注入されている
- `frames_no_person` — 非ゼロなら被験者が画角から外れた
- `mean_body_coverage` — 試行間でドリフトしていたら立ち位置が動いている

> **`hit_count`（総ヒット数）の解釈に注意**: 重力が高いほど跳ね返り周期が短くなるため、
> **技量が同じでも機械的に増えます**。主要指標には使わないでください。

### `events.csv`（1 イベント 1 行）
`trial_start` / `spawn` / `hit` / `drop` / `trial_end`。
打撃ごとに入射・反射速度、法線、`infer_age_ms` を記録します。

記録は試行ごとに `localStorage` へ退避されるので、ブラウザを閉じてもデータは残ります。
